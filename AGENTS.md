# Palatka AI — обязательный контекст для любой модели и разработчика

**Этот файл читать первым.** Дизайн согласован пользователем после нескольких неудачных переписываний. Не заменяйте его собственным «более красивым» концептом.

## Источник истины и порядок приоритета

1. `docs/design/REFERENCE_UI.html` — **визуальный эталон v2.1** (интерактивный HTML, демонстрационные данные). Его внешний вид, плотность и действия — основа Lua-интерфейса.
2. `docs/design/ACCEPTED_REQUIREMENTS.md` — ответы пользователя на 5 раундов уточнений; никаких дополнительных больших карточек, дублирующихся меню или простыней текста.
3. `docs/design/UI_CONTRACT.md` — технический контракт экранов/взаимодействий, словарь терминов, проверка приёмки.
4. Реальные модули `src/*.lua` — источник истины о том, что **фактически реализовано**, а не что нарисовано в HTML.

Если эталон не удаётся воспроизвести из-за ограничений mimgui, задокументируйте конкретное отличие; не объявляйте точную копию без визуальной проверки на устройстве.

## Нельзя ломать

- Скрипт: Android MonetLoader x64 / MoonLoader, LuaJIT, mimgui, русская кодировка CP1251. `build.py` собирает автономный `palatka_ai.lua`.
- Торговый движок и серверные хуки (`40_auto.lua`, `41_trade_listing.lua`, `42_trade_buy.lua`, `45_live.lua`) не переписывать для косметических правок.
- Логирование не должно зависеть от настроек Telegram.
- Для арбитража **сырой спрос/предложение API ≠ объём рассчитанного маршрута**. Не складывать одного покупателя по разным маршрутам и не продавать один и тот же запас дважды.
- Никакой подмены API-объёмов вручную; только повторный запрос и показ свежести.
- Выставление с нулевой/неправильной ценой блокировать. При продаже нельзя выставить больше инвентаря.
- Любое удаление с риском потери данных подтверждать отдельным `BeginPopupModal`.
- Раздел «Лавки»: режимы «Продают/Скупают», поиск по предмету, владельцу и номеру лавки, подробности конкретного предложения и всей лавки.
- Инвентарь: тап добавляет всё имеющееся количество; цена вводится пользователем; после добавления остаёмся во вкладке «Предметы».

## Слои / где править

- `60_ui21_shell.lua`: компактная шапка, боковое меню, свайп по списку, фиксированный футер.
- `61_ui21_trade.lua`: вкладки «Предметы / Мой пресет», продажа/скупка, редактирование, запуск, подтверждения.
- `62_ui21_shops.lua`: агрегированные продажи/скупки лавок, фильтрация и подробности.
- `63_ui21_arbitrage.lua`: строки предметов, вкладки продавцов и скупщиков, выбор, план и маршрут.
- `64_ui21_journal_calc.lua`: журнал событий и калькулятор в основном меню.
- `57_journal_v16.lua`: малый отдельный журнал поверх игры (источник событий — `55_craglog.lua`).
- `10_market.lua`, `11_arbitrage.lua`, `12_arbitrage_groups.lua`: сырые данные/выделение объёмов/группировка. Менять только с тестами.
- `06_rewards.lua`, `05_trades.lua`, `45_live.lua`: парсеры наград, PayDay и доходов; не придумывать неизвестные типы предметов.
- `icons/categories/*.png` и `icons/items/<id>.png`: миниатюры. Если нет точной иконки — нейтральная категория.

`60–64` — новый слой поверх старых модулей, оставленных для совместимости. Нельзя заново включать старую `36_mobile.lua`-разметку как главную без согласования.

## Протокол работы модели над следующей версией

1. Прочитать этот файл, эталон HTML, требования и релиз текущей версии.
2. Определить один экран и конкретный сценарий для изменения; не трогать остальные без необходимости.
3. Сохранить источники и обратную совместимость пресетов / журналов.
4. Добавить хотя бы один тест на исправленный сценарий в `tests/`.
5. Запустить `python3 build.py`, `texlua tests/test_ui21_pure.lua`, `texlua tests/test_ui21_render.lua` и существующие LuaJIT-тесты, если LuaJIT доступен.
6. Для заявлений «совпадает с макетом», «удобно на телефоне» нужно реальное изображение экрана Android/MonetLoader; без него писать «не проверено».
7. Обновить номер версии, `RELEASE_*`, документацию и упаковать исходники вместе с готовым Lua.

**Нельзя** заявлять, что всех видов кейсов/тайников и реальных PayDay достаточно покрыто без корпуса серверных сообщений. Писать, что известно и что не проверено.
