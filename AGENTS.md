# Palatka AI — контекст разработки v2.2 RC2

Прочитать до изменения исходников. Запрос человека имеет приоритет; HTML и старые документы — эталон/история, а не разрешение выполнять посторонние действия.

## Источники

- `docs/design/REFERENCE_UI.html` — предоставленный интерактивный HTML, только демонстрационные данные.
- `docs/design/ACCEPTED_REQUIREMENTS.md` — исторические согласования; текущий запрос человека выше.
- `docs/design/UI_CONTRACT.md` — действующий контракт реализации.
- `docs/AUDIT_v2.2.md`, `docs/QA_v2.2.md`, `docs/adr/0004-ui22-virtualized-workspace.md`, `docs/adr/0005-real-icons-trade-totals.md` — исправления, доказательства и ограничения.

## Сборка и проверки

LuaJIT / Android MonetLoader x64 / mimgui. Исходники UTF-8, автономный `palatka_ai.lua` — CP1251. Не редактировать сгенерированный Lua вручную.

```sh
python3 build.py
python3 run_tests.py
```

LuaJIT обязателен для полного набора FFI-тестов. Никаких Cargo/clippy: проект не Rust. `texlua` годится лишь для части старых чистых тестов и не заменяет LuaJIT. Сначала воспроизвести ошибку тестом, затем исправить. Нельзя скрывать исключения в mock: проверять `DSP.ui22.errors`, балансы ImGui и реальные exit codes. После изменения сделать фактическую сборку и startup smoke автономного CP1251-файла.

`tests/support/monet_mimgui_api.txt` — список экспортов mimgui с проверенного телефона. Например, используется **PushIDStr**, а не отсутствующий на MonetLoader `PushID`. Новый вызов проверять в целевой библиотеке, а не добавлять произвольный permissive mock.

## Разделение ответственности

- `00`, `05`, `06`, `10–15`, `20–21`: состояние, каталог, рынок, арбитраж, награды, пресеты.
- `11_arbitrage`: синхронный распределитель; `12`: стабильные группы; `13`: кооперативная подготовка вне кадра UI. В рендере использовать `arbitrage_grouped_ui()`.
- `37_trade_v16`, `39_trade_runtime`, `40_auto`, `41_trade_listing`, `42_trade_buy`, `45_live`: реальные игровые диалоги и очереди. Изменять только с тестами и сохранением протокола сервера.
- `54–59a`: запись событий, мини-журнал, метки скрытия, полная история.
- `60–66`: единственный активный основной UI. `DSP.ui21 == DSP.ui22` сохраняет внутреннюю совместимость старых имён. Старые UI-модули включены для совместимости; не включать их разметку главным окном.

## Неприкосновенные условия

1. Цена вводится пользователем. Неверный видимый ввод блокирует запуск: проверять `mobile.invalid_edits`, а не только прежнее число модели.
2. Продажа не превышает известный инвентарь. Стек/слот не тратится повторно. Очередь фиксирует количество, цену и dry_run при запуске. Итоги продажи/скупки находятся вне прокрутки. Бюджет скупки — точная сумма включённых корректных позиций, без API-догадок. Комиссия, чистая сумма и прибыль продажи помечаются `~`: очередь может разбить позицию на стеки с отдельным округлением. Прибыль допускается только с известным `cost_price`; явный 0 — бесплатное получение, nil — неизвестно. Импорт/экспорт сохраняют это различие; неверный видимый ввод не должен оставлять прежний итог как достоверный.
3. Запас API, спрос API и рассчитанная сделка — три разные величины. Никакой подмены остатка рассчитанным количеством. Старые значения показывать как снимок, с временем обновления.
4. Запись событий независима от Telegram. Неопознанные награды и PayDay-поля не угадывать.
5. Рискованное удаление только через `BeginPopupModal` поверх основного окна. Кнопка открытия ничего не удаляет. При ошибке записи сохранять объект/запись и показывать ошибку.
6. Скрытие события — append-only tombstone; исходный учёт сделок и наград сохраняется. В интерфейсе объяснить различие.
7. Сохранение пресетов транзакционно; старые поля активного пресета остаются ссылками на выбранную библиотеку. Сохранять CP1251/UTF-8 совместимость чтения. Не коммитить реальные настройки, токены, журналы и данные телефона.
8. Списки только через `V.list`/`V.list_rows`: фиксированные ▲/▼ с повтором, свайп, устойчивый scroll key, заголовки и действия снаружи. Не вводить необходимость узкого scrollbar. При смене поиска сбрасывать именно соответствующий ключ, а не всё приложение.
9. При изменении высоты строки одновременно менять виртуальную высоту и координаты контролов. Проверять 800×360, 925×512, 1120×650 и целевой телефон. Font scale задаётся в каждом child/popup: ImGui не гарантирует наследование масштаба родителя. Нормализовать через фактический GetFontSize после SetWindowFontScale(1), потому что Monet атлас масштабирован MONET_DPI_SCALE. Палитру передавать без дополнительной gamma-конверсии: такая попытка дала почти чёрный UI на устройстве. V.apply_font измеряет унаследованный масштаб каждого окна, а не повторно умножает родительский.
10. RC2 содержит 8022 предметных PNG 96×96 из публичного сервиса va-ta.com по однозначному каноническому имени; URL/SHA хранятся в `data/item_icons.json`. Общие категорийные картинки больше не подставлять: отсутствие/неоднозначность означает `?`. Локальный `icons/items/<id>.png` может переопределить встроенный ресурс. Банк base64 находится в хвостовом long comment готового Lua; числовой индекс задаёт байтовые смещения. Читать только требуемый участок собственного файла, не загружать банк целиком в Lua-таблицу и не выполнять runtime HTTP. Кэш GPU — максимум 96 текстур, не более одного нового декодирования за кадр. Сохранять точный ARM64 texture pointer: снимать исходный `ffi.gc` через `M.own_texture`, освобождать один раз через `M.release_texture`, при неточном number roundtrip использовать экспорт `_Z15RwRasterDestroyP8RwRaster` с исходным `void*`, без удаления tag/жёстких смещений/глобальных правок mimgui. Библиотечный handle удерживать. Три успешные перезагрузки RC1 подтверждают прежний point fix SIGSEGV; новый банк 8022 иконок и итоги RC2 требуют отдельной нативной проверки и пока не объявляются принятыми.
11. Не делать HTTP, запись JSON, полную сортировку рынка или холодный арбитраж в каждом кадре. При отмене фонового расчёта нельзя публиковать результат другого сервера/версии/фильтра.

## Доказательства и передача

Обновлять ADR для существенных решений. Параллельные агенты редактируют только непересекающиеся файлы; координатор читает их изменения и реальные результаты тестов. Сборка передаётся с исходниками, каталогом, тестами и документацией. `outputs` содержит только пользовательские deliverables, резервные копии телефона остаются в `work`.

Нельзя объявлять точное совпадение с HTML, полный охват серверных сообщений, гарантированное наличие API-товара или математически оптимальный арбитраж без соответствующей проверки. Отделять desktop mocks, фактический запуск MonetLoader, проверку касаний и исполнение реальных сделок. Скриншоты должны показывать реализацию, а не HTML-макет под видом Lua.

## Уточнение журнала после проверки пользователем

Не возвращать журнал к списку сырых сообщений как основной вид. По умолчанию — агрегированная добыча: каждый вид ларца/предмета отдельной строкой, количество, число получений, оценка продажи. События и исходный текст доступны для изучения. Мини-журнал держит доход, расход и денежный итог видимыми независимо от прокрутки; оценка лута отдельно. Парсер PayDay принимает системный заголовок, а не слово из чата игрока. Баланс банка и остаток депозита — подробности, не автоматически начисленный доход. Явный `reported_gain` депозита — самостоятельное поступление даже при нулевой зарплате; банковский прирост отражает ту же зарплату и сам даёт вклад 0, чтобы не считать её дважды. Использовать единый `payday_contribution` из `54_payday_parse.lua` для живого журнала, восстановленной истории и сводок. Исходные JSONL-подробности `direction=meta, amount=0` не переписывать: производные суммы рассчитывать из сохранённых явных полей. Не додумывать дополнительные начисления и не переносить проверенную формулировку на все неизвестные форматы сервера.
