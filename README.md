# Palatka MCR Local 3.0.0-local.8

В этой ветке актуальная самостоятельная сборка — **[palatka_mcr_local.lua](outputs/palatka_mcr_local.lua)**.
Файл `palatka_ai.lua` в корне относится к прежнему Palatka AI и не является этой сборкой.
[Инструкция и проверенные ограничения](mcr_copy/LOCAL_MODE_RU.md).

- `/crr` — основной интерфейс; `/parb` — арбитраж.
- `/crrupdate` — проверить и установить новую сборку из канала `mcr-local`.
- Ключ MCR, MLoader и установленный Market Helper не требуются.
- Список лавок и цены Mobile I–III: публичная база Market Helper и свои сканы.
  Обновление при запуске, каждые две минуты и перед расчётом с двухминутным кэшем.
- Арбитраж разделяет серверы, валюты и модификации, ограничивает объём остатком,
  спросом и бюджетом, учитывает комиссию с округлением по лоту. Показывает возраст
  снимков; самостоятельно сделки не выполняет.
- Каталог 9069 ID и каталог скупки встроены. Настройки и пресеты хранятся локально.
- Обновления проверяются каждые пять минут, сообщение о новой версии — один раз.
  Установка только по команде, с SHA256, проверкой Lua и резервной копией.

local.8 исправляет обновление инвентаря, настройки своего Telegram-бота,
поиск улучшенных предметов и выбор ID при одинаковых названиях. Запоздавшие
ответы не перезаписывают новый экран. Установщик учитывает активную скупку,
HTTP использует прошедшее время, ожидание UID ограничено без подделки готовности.

Сборка проверена 12 Lua-наборами и 13 Python-тестами. Нативная проверка local.8
на Android остаётся открытой: это кандидат, а не объявленный стабильный релиз.
Снимки сторонней базы могут отставать от игры; гарантированная прибыль не заявляется.
Закрытая история/облако/бот MCR не предоставляются без его сервиса. Для Telegram
можно настроить собственного бота. Публичный endpoint MCR при проверке вернул 403;
вместо него используется доступный источник Market Helper, без обхода ограничений.

# Palatka AI v2.2.3 — RC4.1

**Статус:** кандидат RC2, 51/51 автопроверок, exit code 0. Встроены 8022 предметных изображения и фиксированные итоги продажи/скупки. Нативная проверка этих двух изменений RC2 ещё ожидается. Исторические проверки RC1, включая исправление SIGSEGV, и оставшиеся ограничения перечислены в [QA](docs/QA_v2.2.md); они не заменяют проверку нового банка иконок на телефоне.

Торговый помощник для Arizona RP / Android MonetLoader x64 с переработанным мобильным интерфейсом. Готовый `palatka_ai.lua` автономен относительно исходников Palatka и Market Helper: каталог 9069 ID и банк 8022 предметных PNG встроены.

## Установка

1. Сохраните копию существующего `palatka_ai.lua` и каталога `PalatkaAI`.
2. Скопируйте новый `palatka_ai.lua` в каталог скриптов MonetLoader вашей игры. Нужны стандартные библиотеки игрового окружения `mimgui` и `encoding`.
3. Открыть основное окно — `/crr`, плавающий журнал — `/crlog`.
4. В торговле выбрать продажу/скупку. Во вкладке «Предметы» источник, скан инвентаря и ручное добавление доступны через кнопку источника в фиксированной нижней панели. Вкладки и поиск находятся в одной строке. Цена задаётся вручную в «Мой пресет».
5. До реального выставления проверить инвентарь, цену, количество и режим ТЕСТ/РЕАЛЬНО. Сборка не требует Market Helper; импорт его JSON остаётся необязательной функцией.

## Предметные изображения

В комплекте 8022 PNG 96×96, полученных по уникальным каноническим именам из того же публичного [сервиса изображений](https://va-ta.com/api/items/icon/by-name/img), который использует Market Helper. Из 8207 первоначальных кандидатов исключены 179 ответов HTTP 404 и шесть ID с неоднозначными именами после trim/casefold. Соответствия, URL и SHA-256 записаны в `data/item_icons.json`. Права на игровые изображения принадлежат их правообладателям, Arizona Games; новые AI-иллюстрации не создавались.

Общая картинка категории больше не подставляется вместо предмета. Если имя/ID неоднозначны или изображения нет, показывается `?`. Пользовательский `PalatkaAI/icons/items/<ID>.png` имеет приоритет, если Android разрешает чтение каталога.

Иконки находятся в индексированном комментарии в конце готового Lua. При показе читается только нужный участок собственного исходного файла; весь base64-банк не хранится таблицей строк в Lua heap. В игре нет HTTP-загрузки изображений. Кэш GPU ограничен 96 текстурами, декодирование — одной новой текстурой за кадр. Готовый файл существенно больше RC1: его нужно переносить без изменения байтов, не обрезать комментарий и не заменять скомпилированным Lua-байткодом без банка.

## Итоги торговли

Внизу обеих торговых вкладок постоянно видны итог и действия. Скупка показывает точную сумму настроенных включённых позиций `цена × количество`; это бюджет пресета, а не обещание наличия товара или успешного исполнения. Продажа показывает выручку и приблизительные комиссию/сумму чистыми. Знак `~` учитывает возможное округление комиссии по отдельным инвентарным стекам.

Прибыль продажи показывается только при известной себестоимости всех включённых позиций. Её можно задать в подробностях предмета: `0` означает явно бесплатное получение, пустое/неизвестное значение не превращается в нулевую стоимость. Если цена или количество введены неверно, полный денежный итог не выдаётся за рассчитанный.

## Новый журнал

«Добыча» показывает каждый предмет/улучшение отдельно: количество, число получений, приблизительную стоимость продажи и остаток без известной цены. По нажатию можно изучить получения и источники. «События» сохраняет хронологию, категории, поиск и подробности. Периоды — сессия, сегодня, всё время.

Мини-журнал переключается между добычей и событиями. Доход, расход, денежный итог и оценка лута остаются видимыми под списком. Стоимость непроданных предметов **не прибавляется** к полученным деньгам. Рыночная оценка и наличие товаров не гарантированы; неизвестная цена явно отмечается.

## Сборка и проверка

```sh
python3 build.py
python3 run_tests.py
```

Нужны Python 3 и LuaJIT. Исходники — UTF-8, готовый Lua — CP1251. Новых зависимостей приложения не добавлено. Необязательное настольное обновление ресурсов через `tools/fetch_item_icons.py` использует Python/Pillow; на телефоне этот инструмент не нужен. `run_tests.py` выполняет сборку и все активные регрессии, сохраняет exit codes в `docs/test-results.json`; ошибка любой проверки приводит к ненулевому коду.

Проверки и их пределы перечислены в [QA](docs/QA_v2.2.md). Старые изображения в `docs/design` — референсы. Реальные снимки разработки находятся в `docs/screenshots`; их состояние сборки оговорено в QA.
