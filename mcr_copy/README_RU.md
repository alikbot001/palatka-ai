# Palatka MCR — полная клиентская копия + локальный арбитраж

Экспериментальная отдельная сборка `outputs/palatka_mcr_preview.lua`.
Основа — полный извлечённый клиент MCR Mobile 1.15.5 автора Sand (1 469 406 байт),
с сохранением исходного интерфейса, функций и авторизации. Авторство оригинала
сохранено; лицензия на его распространение в извлечённом файле не обнаружена.
Не обозначать сторонний код как самостоятельно написанный или перелицензированный.

Этот файл не заменяет штатную main Palatka AI. Её build.py и исходники не менялись.

## Новое

- Пункт **Арбитраж** в левой панели MCR и команда **/parb**.
- Расчёт маршрутов из открытых лавок и внешних снимков с учётом количества,
  бюджета, комиссии и улучшений. Один объём выделяется один раз.
- Центральная и правая панели используют экземпляр mimgui, тему, размеры и
  обработку свайпа оригинального MCR. Нового отдельного основного окна нет.
- Кнопки «Найти продавца/скупщика» отправляют только `/findilavka` по нажатию.
  Автоматических покупок/продаж в дополнении нет.
- Локальная база `neomloader/PalatkaMCR/market.json`, атомарная запись.
- Кнопка **Кэш рынка Palatka** читает существующий файл
  `PalatkaAI/market_101.json`, `market_102.json` или `market_103.json` по текущему
  мобильному серверу. Внешние данные сохраняют исходное время наблюдения.
- Кнопка **Импорт JSON** читает `PalatkaMCR/import.json`, формат ниже.
- Также перехватываются полные просмотренные снимки из исходного MCR API,
  когда присутствуют сервер, ID предметов и числовое время наблюдения.

Свежесть по умолчанию 1 час. Неизвестные количество, время или идентичность
предмета не превращаются в выдуманный маршрут. До 128 лавок в памяти,
256 строк на сторону снимка, 20 000 сравнений за расчёт; при достижении лимита
сравнений показывается предупреждение о неполном списке. Порядок эвристический,
глобальная математическая оптимальность не обещается.

Живая загрузка публичной базы сайта MCR здесь **не реализована**: её доступность
для независимого клиента не подтверждена. Кнопка кэша не обновляет данные в сети.
Новый локальный арбитраж сам не требует ключа MCR; исходные функции MCR продолжают
использовать исходную серверную авторизацию. Серверная часть MCR не скопирована.

## Импорт

```json
{"schema":1,"shops":[{"server":"IP:PORT","shop":121,"owner":"Player_Name",
"at":1794140000,"source":"import","sell":[{"id":"4003","variant":"9:0",
"name":"Молот Тора","currency":"SA$","price":100000,"qty":2}],"buy":[]}]}
```

`server` должен совпадать с сервером, показанным в арбитраже (IP:PORT).
`at` — фактическое время наблюдения Unix, а не время скачивания/импорта.
`variant` — улучшение и встроенный предмет через двоеточие; `0:0` — базовый вариант.
Не включайте ключи, токены и личные настройки в импорт.

## Сборка и проверки

```sh
python3 build_mcr_copy.py
luajit mcr_copy/tests/test_engine.lua
luajit mcr_copy/tests/test_app.lua
luajit mcr_copy/tests/test_external.lua
luajit mcr_copy/tests/test_ui.lua
python3 -m unittest discover -s mcr_copy/tests -p 'test_*.py'
```

Сборщик сверяет SHA256 основы, уникальность девяти вставок и синтаксис LuaJIT.
Тест удаляет эти вставки и проверяет побайтовое восстановление оригинала.
Все 19 регистраций окон оригинального клиента сохранены.

Новые тесты и компиляция пройдены. Это desktop-проверки, не нативная приёмка.
Общий старый набор репозитория: 69/111 как до, так и после изменений; список
ошибок сохранён в `outputs/mcr_copy_verification.json`. Они не скрывались и
не исправлялись попутно. Независимый reviewer не завершился из-за лимита сервиса.

## Установка предварительной сборки

Сборка ещё не установлена и не запускалась на телефоне. Для будущей проверки:

1. Сохранить MLoader.lua и папку `config/MCRM CFGs` в резервную копию.
2. Через менеджер скриптов выгрузить оригинальный MLoader/MCR, чтобы одинаковые
   команды и игровые обработчики не работали одновременно.
3. Положить `palatka_mcr_preview.lua` в `neomloader` и загрузить его менеджером.
4. `/mcrm` открывает исходный MCR; `/parb` — новый раздел арбитража.
5. Проверить пустой экран, скан лавок, смену сервера и работу касаний.

Резервная копия настроек нужна: исходный клиент использует те же каталоги
`config/MCRM CFGs`. Stable/обновлятор существующей Palatka не переключались.
