# Локальная сборка 3.0.0-local.1

Сборка: `python3 build_mcr_local.py` → `outputs/palatka_mcr_local.lua`.
Основой остаются исходные окна и игровые обработчики MCR Mobile 1.15.5.
Локальная готовность игрового клиента заменяет жизненный цикл лицензии;
не создаются фиктивные ключи или положительные ответы сервера авторизации.

Удалены семь встроенных лицензионных блоков, включая ограничения в разборе
инвентаря, подготовке продажи и сохранении настроек/пресетов. Проверки игровых
слотов, владения и серверных подтверждений не удалялись.

Новая папка: `neomloader/config/Palatka MCR Local`. Старые настройки и ключ
MCRM не загружаются. Каталог 9069 предметов встроен в Lua.
HTTP к MCR и другим неразрешённым источникам блокируется с явной ошибкой;
разрешены игровые API Arizona и собственный Telegram-бот. Удалённые базы,
облако, уведомления MCR и закрытые серверные сведения не имитируются.

## Подтверждённые результаты

- Четыре Lua-набора арбитража, UI и адаптеров проходят.
- Четыре Python-теста проходят: сохранность preview, пустой ключ/сохранение
  настроек и пресетов, блокировка запросов без фиктивного успешного ответа,
  исполнение исходного обработчика продажи с пустым ключом.
- В тесте обработчика продажи проверены отсутствие отправки без подтверждения
  владельца, пустой список, подтверждение выставления и ограничение тремя
  попытками без ответа. Пакеты имитируются на компьютере; реальные сделки
  этим тестом не подтверждаются. Исходный флаг `sendPresetSell` означает конец
  обработки очереди и сам по себе не доказывает успешное выставление.
- Сборка компилируется LuaJIT.
- 1343 нормализованных прототипа функций совпадают с исходным MCR.
- Файл установлен через ADB как `neomloader/palatka_ai.lua`.
- SHA256: `5e439c42abf7d0f2757f02f611dd653c3b2c58facdb4d0834c20cae012bd995d`.
- В журнале телефона зафиксирован запуск palatka_ai.lua в 21:14:14.
- На телефоне создана новая папка и MCRM-settings.json; JSON прочитан и
  проверен: ключ `main.userKey` пустой, сохранено 18 разделов настроек.

Все экраны и реальные сделки пока не прошли нативную проверку. Не объявлять
всю функциональность подтверждённой по одному запуску и пустому ключу.
Возможности, требующие сервисов MCR, остаются недоступны в этом локальном варианте.

При проверке 9 ноября обнаружено, что лаунчер `.web` запускает установленный
официальный пакет `com.arizona21.game`. При этом APK `.web` содержит собственные
NeoMLoader и игровую Activity. Проверенный прямой запуск нужного клиента:

```sh
adb -s RF8X60PHTSB shell am start -n com.arizona21.game.web/com.arizona.game.GTASA
```

После прямого запуска получен свежий журнал NeoMLoader 1.0.68 (build 168):
9 ноября в 07:09:12 загрузился `palatka_ai.lua`; в 07:09:13 загрузчик сообщил
об успехе. Повторно прочитаны настройки: ключ пустой, 18 разделов.
Это исправляет предварительный вывод о неверном пакете: причина перехода
в официальный клиент связана с маршрутом запуска лаунчера.

Клиент остановился на подключении/входе в игровой аккаунт. Временная копия
с автоматическим открытием меню не дала видимого окна на этом этапе;
это не считается успешной проверкой UI. Обычный файл возвращён на телефон,
его SHA256 совпадает с указанным выше; процесс тестового клиента остановлен.
Для проверки окон, команды и лавок остаётся войти в аккаунт в клиенте `.web`.
