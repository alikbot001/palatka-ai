# Актуальные данные, лотовая комиссия и локальные каталоги

Status: candidate local.7, desktop verified; Android acceptance pending.

## Context

Пользователь требует законченный клиент без ключа MCR и ручного поиска базы.
Проверка агентами выявила пропуск прибыльного лота после округления на единицу,
пустой каталог скупки на чистой установке, обращения ID-каталога к заблокированному
MCR и ложный успех неактивного MCR-бота. Публичный MH API отвечает без ключа,
MCR public token endpoint ответил 403; закрытый источник не обходится.

## Decision

Обновлять MH-снимки при старте/по двухминутному таймеру/перед расчётом. Продолжать
автопересчёт после явного запроса арбитража; отменять его при стопе или изменении
параметров. Сетевой отказ сохраняет кэш с явной подписью, TTL и отрицательное время
проверяются перед использованием маршрута. Стоимость/спрос/остаток не подменяются.

Предварительный фильтр прибыли учитывает дробный остаток после комиссии;
окончательный результат всё равно требует положительной прибыли по целому лоту.
Отдельный регрессионный пример: 100×100 → 103×100 при2% даёт94, а не0.
Каталог скупки — отдельный список имён из ID-каталога с сохранением пользовательских
строк. Обе операции обновления локальны. MCR Telegram выключен; собственный бот
требует явной конфигурации, маршрутизатор возвращает реальный результат постановки
в очередь, а не успех отсутствующего транспорта.

## Consequences

Нет гарантии наличия товара или оптимального решения бюджета: расчёт основан на
наблюдаемых объявлениях. Смена сервера, удаление лавки и истечение снимка исключают
старые действия. Закрытые облачные данные MCR не создаются фиктивно. Нативные
торговые проверки и специфичный парсер игровой UID остаются за пределом desktop QA.
