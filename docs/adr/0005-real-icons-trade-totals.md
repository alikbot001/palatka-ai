# ADR 0005 — Предметные иконки и фиксированные итоги торговли

**Status:** реализовано в RC2; 48/48 автопроверок прошли. Нативная приёмка новых иконок и итогов ожидается в [QA](../QA_v2.2.md).

## Context

Пользователь запросил реальные изображения предметов и постоянно видимые суммы продажи/скупки. Подстановка одной общей картинки категории не выполняла требование. Прежние торговые строки не давали фиксированного бюджета/выручки. API-оценка не является известной ценой закупки конкретного запаса.

Источником изображений выбран тот же публичный сервис `va-ta.com/api/items/icon/by-name/img`, который вызывает Market Helper в публичном `market.js`. Идентификатор API основан на имени, поэтому совпадение имён после очистки/trim/casefold считается неоднозначным, а не поводом выбрать произвольный ID.

## Decision

1. Подготовить ресурсы вне игры. Заморожены 8022 PNG 96×96: 8207 первоначальных кандидатов минус 179 HTTP 404 и шесть ID с каноническими коллизиями. Сохранить имя, исходный URL, размер и SHA-256 в `data/item_icons.json`. Права на игровые изображения остаются у Arizona Games/правообладателей; AI-иллюстрации не создаются.
2. Упаковать base64 в хвостовой long comment автономного CP1251 Lua. Индекс содержит байтовые offset/length. При показе читать ограниченный срез собственного файла и декодировать один PNG; не создавать Lua-таблицу всех base64-строк и не делать runtime HTTP. Такой формат требует сохранения исходного файла и его байтов, включая комментарий.
3. Разрешать ID/имя с проверкой соответствия, снимая суффикс улучшения с имени. Локальный `icons/items/<ID>.png` имеет приоритет. При отсутствии/неоднозначности показывать `?`; категорийная подмена удалена. Совпадение готового рисунка у нескольких предметов само по себе не доказывает уникальность модели игры: provenance описывает ответ публичного сервиса, а не независимую сверку каждого игрового ассета.
4. Ограничить GPU-кэш 96 текстурами и новым декодированием за кадр. Сохранить exact-pointer release из ADR 0004, без преобразования tagged адреса через Lua number. Не вводить постоянную утечку вместо правильного освобождения.
5. Вынести торговые итоги в закреплённую нижнюю область обеих вкладок. Бюджет скупки — точная сумма настроенных включённых корректных `price × qty`, без комиссии продажи и предположений наличия API. Выручка продажи — отдельно; комиссия, чистая сумма и прибыль помечены `~`, потому что очередь может разбить строку на стеки с отдельным округлением.
6. Прибыль продажи вычислять только при известном `cost_price` всех включённых строк. Явный 0 означает бесплатное получение, nil — неизвестно. Сохранить это различие при ручном добавлении, импорте и экспорте. Неверный ввод цены/количества или переполнение скрывают полный итог; неизвестная/неверная себестоимость скрывает прибыль, а не превращается в ноль.

## Consequences

Ресурсы доступны без сети и не требуют каталога Market Helper на телефоне. Отсутствующие 179 ответов и неоднозначные имена остаются без встроенной картинки; полнота 9069 ID не обещается. Пользователь может добавить своё точное изображение по ID.

Автономный Lua стал значительно больше (71511184 байта в проверенном build). Long comment исключает удержание всего банка как строковых констант Lua, но загрузчик всё равно читает/разбирает большой файл. Это не доказательство нулевой пиковой памяти или отсутствия задержки запуска; требуется нативная проверка. Компиляция в bytecode или изменение переводов строк без пересчёта индекса могут разрушить ресурсный банк.

`test_v22_real_icons.lua` проверяет identity, decode/ограниченное чтение, неизвестный ресурс, reuse и отсутствие общей подмены. `test_v22_trade_totals.lua` проверяет арифметику, неизвестную/нулевую себестоимость, ошибки ввода, экспорт/импорт и закреплённые контролы на нескольких размерах окна. Полный source-прогон — 48/48, exit code 0. Исторические нативные проверки RC1 не подтверждают новый банк и footer; текущая нативная приёмка RC2 пока PENDING. Реальная торговля, все касания и FPS этим решением не объявляются проверенными.
