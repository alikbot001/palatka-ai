# 0013 — Владелец лавки и проверка перед поиском

**Status:** Candidate local.11; native acceptance pending.

## Context

Пользователь дважды обнаружил другого владельца на месте указанной лавки.
Две публичные выгрузки одного сервера показывают фактическую смену владельца
одного номера с разницей во времени скана около 29 минут. Сторонние снимки
не являются состоянием игры в реальном времени.

Дополнительно воспроизведены две ошибки адаптера: обновление записи могло
освежать старый скан, а одинаковое время разных владельцев смешивало стороны.

## Decision

Использовать валидный scanned_at, когда он указан; updated_at оставлять только
для старого формата без времени скана. При одинаковом времени и разных владельцах
сохранять пустой снимок с owner_conflict до более нового скана. Локальное
наблюдение имеет приоритет перед внешним при одинаковом времени.

Все четыре нативные кнопки маршрута по снимку и обе стороны арбитража вызывают
единую проверку номера, сервера и захваченного владельца. До отправки findilavka
принудительно обновлять публичную базу и сверять владельца повторно; отказ сети,
исчезновение, конфликт, истечение времени или смена сервера отменяют команду.
Повторное нажатие и повтор callback не отправляют вторую команду.

## Consequences

Нужен ответ базы для маршрута по публичным снимкам. Проверка обнаруживает
изменения, уже отражённые источником; она не доказывает наличие товара сейчас.
Старые сохранённые updated_at нельзя достоверно преобразовать в исходное время
скана. Пересборка не очищает журнал закупок и пользовательские настройки.
