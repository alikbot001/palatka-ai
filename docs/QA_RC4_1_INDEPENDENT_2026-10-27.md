# Palatka AI — RC4.1 (27.10.2026)

## Разделение проектов

Palatka AI — отдельный автономный инструмент, и это именно её Lua-сборка. Market Helper — только внешний пример для анализа игровых диалогов и возможной причины некорректного `qty=1`. Никакой зависимости `require`/`dofile` Market Helper, общего runtime, передачи его пользовательских файлов или принудительной установки нет.

## Изменения RC4 + RC4.1

- Исправлен опасный источник неверной интерпретации остатка: API может сообщать `1` **слот**, а не `1` предмет. Объём API маркируется непроверенным; прямой игровой скан и подтверждённое пользователем количество показываются отдельно.
- Для сравнения игровой цифры нужны точный сервер, лавка, владелец, предмет, улучшение, сторона и цена, свежесть не более 120 секунд и открытая лавка. Если нет надёжных данных, выводится «неизвестно», а не 1 или 45 000, выдуманные из других источников.
- Поправка количества делается только по отдельной кнопке; старое API-значение сохраняется, новый запрос рынка сбрасывает поправку.
- **RC4.1:** во время подтверждения из игры повторно проверяется текущий открытый снимок. Предотвращён сценарий, когда цифра 45 000 была на экране, но перед нажатием сменились лавка/количество — теперь операция отклоняется без мутации.
- UI: крупные кнопки «Предложения» на карточках и «Выбрать / Снять выбор», «Уточнить», «Метка» у предложений арбитража; детали лавки прокручиваются отдельно с фиксированными кнопками ▲/▼. Сохранены прежние функции торговли, сканирования, ценовых ориентиров, пресетов, журнала, 3D-метки и GPU LRU изображений.
- В арбитраже цифры API не становятся доказанным игровым количеством; расчёт прибыли остаётся *оценкой* по снимку. Отсутствие проверенного остатка не исправляется искусственным ростом количества.

## Нативный сценарий без игровых сделок

1. В «Лавки → API» найти дрова с отображаемым объёмом `1` и записать номер лавки/цену. Открыть её и в игре, включить «Скан лавки»: если игровой протокол явно содержит `45 000`, скрипт должен показать две разные цифры. Если количество в игровом пакете отсутствует, оно должно остаться неизвестным.
2. Нажать «Принять из игры» только при действительно известном игровом количестве; после обновления рынка поправка должна сброситься. Проверить отмену/ручную корректировку и закрытие лавки перед подтверждением.
3. В арбитраже нажать **«Предложения»**, выбрать/снять лавку крупной кнопкой, открыть маршрут и проверить затраты, валовую выручку, комиссию, чистую выручку и прибыль.
4. Проверить ▲/▼, модальные окна и корректность изображения нескольких предметов на телефоне. Отдельно — новые 3D и торговые механизмы по безденежному сценарию; при ошибке снять лог MonetLoader или обезличенный игровой пакет.

## Незакрыто

- Реальное выставление продажи/скупки в Arizona RP в этой ветке **не подтверждено**. По умолчанию включён тестовый режим, не считающийся доказательством отправки.
- Точный источник ошибки дров 1 вместо 45 000 на конкретной лавке неизвестен без её актуального пакета; доказан лишь возможный путь `qty=1` как заглушки в референтном источнике.
- 3D-метка, реальные величины/масштаб UI, память PNG/LRU и текущая мобильная интеграция требуют MonetLoader.
- `docs/QA_RC4_QUANTITY_UX_2026-10-27.md` содержит подробности исходных изменений RC4 и предыдущие пределы проверок.
