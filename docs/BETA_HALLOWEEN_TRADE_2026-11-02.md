# Halloween Trade Beta Fix — 2026-11-02

**Статус: BETA, нативная проверка MonetLoader / Arizona RP Mobile II не пройдена.**

Этот фикс внедрён в исходную ветку `main` для тестирования, а не объявлен стабильным игровым релизом.

## Изменения

- `src/40_auto.lua`: запись ID, стиля и названия диалогов во время продажи и скупки; сопоставление новых диалогов ввода цены с актуальным кликом по конкретному слоту, а не только со старым списком ID.
- `src/41_trade_listing.lua`: фиксация ожидания нового диалога до отправки пакета клика по слоту.
- `src/45_live.lua`: ограниченный по размеру и времени буфер для структурно неполных JSON-сообщений по отдельным `interfaceid/subid` до вызова парсера.
- `tests/test_halloween_trade.lua`: тесты известных/новых ID, старых и посторонних диалогов, независимых пакетов и разрыва JSON после байта 8192.

## Что НЕ подтверждено

- Реальное значение `interfaceid` или структура JSON пакета 220/63 в новом обновлении сервера. В рабочем коде они оставлены без догадок.
- Что сообщение об ошибке декодирования на 8193-м символе вызвано именно multipart-транспортом. Буфер покрывает один возможный сценарий.
- Исполнение настоящей продажи или скупки на Android/MonetLoader: нужны реальные игровые логи.

## Публикация и обновления

Ветка `main` содержит экспериментальный фикс в исходниках и сгенерированном CI автономном скрипте. Версия `version.json` и OTA-скрипт **не меняются**: автоматическое обновление не должно показывать этот фикс как новый стабильный выпуск. CI проверяет синтаксис и тесты, но не заменяет проверку в игре.

При ошибках отправить (без паролей/персональных данных) строки `TRADE incoming dialog`, `LIVE JSON`, `PRESET sale packet` из диагностического лога. Провести проверку сначала на одном дешёвом предмете.
