# Palatka AI — план стабилизации и центра управления (2.9.7+)

Дата: 2026-11-01. Базовая ветка: main, версия в build.py и 00_core.lua — 2.9.6.
Статус: рабочий план; каждая задача принимается **только** по тестам + подтверждению в Android MonetLoader.
Market Helper — образец поведения, а не runtime-зависимость.

## Неприкосновенные правила
- Сохранить все пользовательские настройки, пресеты, историю и журнал; перед миграцией сделать checkpoint.
- Не писать настройки на каждый кадр. При сбое сохранения показывать ошибку и не сообщать об успехе.
- Не путать предложения API с реальными сделками, ожидаемую прибыль с фактической, неизвестное количество с нулём.
- Не отправлять торговые пакеты/команды до явного запуска, а тестовый режим не должен отправлять их вообще.
- Не подменять успешной сборкой тесты на телефоне.
- Интервалы авто-пиара должны соответствовать ограничениям конкретного игрового сервера. Параметры не предназначены для обхода лимитов.

## Фаза A — стабилизация (P0)
1. Сохранение арбитража транзакционно: подтверждённая покупка/продажа не меняет учёт при отказе диска.
2. Нажатие «Нет предмета» и «Нет лавки» не закрывает мини-агент, поддерживает «Вернуть» и «Следующий».
3. При ошибке UI не исчезает состояние сессии; статус и traceback видны через диагностику.
4. Вся информация о версии берётся из DSP.version; актуальный номер имеет сборка, а не текст модулей.
5. Добавить регрессии на старт/отмену/рестарт агента, защиту от повторных подтверждений, устаревший API и сохранение.
6. Разделить 4 типа статуса теста: syntax, model/mock, Android/UI, реальная торговая операция.

## Фаза B — единый центр управления (P0/P1)
Экран «Управление» в навигации (связь с существующими модулями, без дублирования движков).
Все параметры имеют стандартное значение, допустимые границы, сохранение в настройках, кнопку «Вернуть стандартные».
Изменение настройек **не запускает автоматически** торговлю и рекламу.

### Выставление лавки и торговля
- Режим ТЕСТ/РЕАЛЬНО, мгновенный STOP, индикатор операции и прогресс N/M.
- Наборы продажи/скупки: цены, количество, активность, бюджет, проверка инвентаря.
- Настраиваемые паузы **между отдельными выставлениями** (продажа/скупка); служебные ожидания протокола менять нельзя без игровых тестов.
- Следующий этап: повторы только неподтверждённых шагов, ограничение повторов, таймауты и отказ при другой версии диалога.
- Автоматическое перевыставление лавки — отдельная будущая опция, по умолчанию ВЫКЛ; невозможно обещать без проверенного игрового протокола.

### Авто-пиар
- Каждый шаблон: заголовок, строки-команды, включение, очередь, случайный выбор, интервалы min/max, лимит, пауза между строками.
- Общие параметры: задержка после входа, минимальный интервал между циклами, лимит сообщений на сессию, бесконечный цикл, автовосстановление только с явным opt-in.
- Видимые: активный шаблон, текущая команда, статус, отправлено, осталось секунд, последняя ошибка.
- Прерывание по потере соединения / STOP; никогда не запускать после установки по умолчанию.
- Примечание: «отправлено из Lua» ≠ «принято сервером». Нужна проверка ответа сервера.

### Рынок / лавки / ломбард
- Частота обновления API и локальный TTL снимков, ёмкость кэша и источник сведений.
- Раздельные снимки серверов; восстановление в рамках дня, сброс достоверности после 05:00.
- Скан ломбарда: запуск вручную у нужного меню, статус, непрочитанные страницы, отсутствие дубликатов, осторожный ручной импорт неподтверждённых пакетов.
- Скан обычной лавки: ID, владелец, время, завершённость и кнопка перепроверки.

## Фаза C — точный арбитраж (P1)
- Сопоставление ID + enchant + server, количеств и времени; одна партия тратится только один раз.
- Предложения «нет лавки / нет товара / другой владелец» исключаются из текущих маршрутов до подтверждённого обновления.
- Формулы: затраты, валовая выручка, комиссия, чистая выручка, прибыль, ROI, резерв, неизвестные издержки.
- Проверки на 1/5/1000 единиц, отсутствие спроса, частичные сделки, округление комиссии и переподключение.
- Мини-агент сохраняет маршрут после отказа и позволяет пропустить/вернуть/пересчитать.

## Фаза D — журнал и производительность (P1)
- Единый event source, дедупликация чеков, отдельные суммы денег и оценка нераспроданного лута.
- Виртуализация всех длинных списков, свайп с инерцией, FPS и выделения памяти без сортировки/HTTP в кадре.
- Профили на Galaxy A15: 10/100/1000 записей, 60 минут активности и после смены ориентации.
- Логи без токенов, сетевых идентификаторов и приватных данных.

## Фаза E — выпуск (P0)
1. Проверить Python-сборку и LuaJIT-компиляцию итогового CP1251 standalone.
2. Запустить все активные регрессионные тесты с exit code, обновить docs/test-results.json.
3. Android: открыть каждый экран; прокрутка, ресайз, мини-агент, паузы, reconnect, маркет, ломбард, торговая очередь только с разрешения пользователя.
4. Заменить старые «2.9.3» в runtime-диагностике; выложить точный номер, SHA, changelog.
5. Только после успешной приёмки merge в main и обновить готовый palatka_ai.lua; проверить /crdiag и загрузчик обновления.

## Критерии готовности
- Ни одной известной воспроизводимой ошибки P0.
- Настройки не теряются и откатываются при записи с ошибкой.
- Точное состояние отправок/очереди/паузы видно пользователю; STOP работает немедленно.
- Изначальные пресеты и журнал читаются после обновления.
- Все проверки разделены на PASS / FAIL / NOT RUN, нативные тесты не помечаются PASS без наблюдения.
