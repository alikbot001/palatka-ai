## Исправления

1. `src/11_arbitrage.lua` и `src/13_arbitrage_async.lua`: допустимы потенциальные маршруты, где лавка публикует **обе стороны** одного точного предмета/улучшения. Пометка `same_shop` предупреждает, что возможность купить/затем сдать по этим ценам на сервере ещё надо подтвердить, поскольку объявление — не сделка.
2. **Риск спроса:** настройки нового/мигрированного профиля используют `max_age=600с`, `include_unknown=false`, `safety_pct=10%`. План оставляет 10% неподтверждённого спроса нераспределённым. Этот резерв не делает покупку безопасной и не доказывает наличие 90/100 шт. Перед крупной покупкой сверять цену, qty и допустимость продажи в целевой лавке. Ручное исправление количества через редактор предложения помечает проверенный пользователем остаток. Смена снимка сбрасывает эту проверку.
3. Жадный распределитель не учитывает остаток скупщика дважды при нескольких продавцах; `safety_pct` включён в синхронный и кооперативный ключи кеширования. Объёмы и налог считаются без неточного умножения больших количеств на 100.
4. `src/63_ui21_arbitrage.lua`: виден возраст снимка, резерв 0/10/20%, переключатель 5/10/30 минут; кнопка уточнения объёма предложения, отключение устаревшего маршрута при обновлении рынка. Указаны направления «КУПИТЬ / ПРОДАТЬ», возможная сделка в одной лавке и риски. «Лучший план» по-прежнему эвристика, не доказанный оптимум.
5. `src/50_overlay.lua`: показан другой смысл рыночной подсказки: **сравнение только с другими лавками** того же item/enchant/server, с данными не старше 10 мин. Если нет данных, оценка не выдумывается; две независимые лавки нужны для уверенной цветной оценки. Цена собственного предложения не делает себя же дешёвым товаром. API-котировки отделены от свершившихся продаж. Сравнения кешируются и не запускают сеть/сортировки в каждом кадре. Более крупное окно с фиксированной постраничной навигацией, большим закрытием и читаемыми карточками. Нативный пиксельный результат не проверен.
6. `src/43_calculator_nav.lua`, `src/64_ui21_journal_calc.lua`: 1000000 → **1.000.000**, 10000000 → **10.000.000**. Исходные числовые операнды/точность вычислений остаются без разделителей, десятичная часть отображается после запятой. Избегаем scientific notation для обычных целочисленных сумм.
7. Ранее добавленные кнопки редактора пресета «Рынок», «Скупка», «Сегодня» сохранены. Первые две основаны на медианах **наблюдаемых** объявлений; «Сегодня» не генерирует среднюю цену завершённых продаж, если источник таких сделок отсутствует. Предыдущая проблема «Выставить» остаётся открытым **нативным** вопросом: доступные тесты не доказывают, что именно игровая очередь работает на MonetLoader. Проверяйте видимый режим ТЕСТ/РЕАЛЬНО до возможного выставления. Не проводить сделки для этой проверки без осознанного разрешения.

## Нативная проверка без игровых сделок

1. Открыть сканируемую лавку, проверить обе стороны одного точного предмета и количество. Сверить подсказку: «120 000, рынок 120 000» **не должно** давать «дёшево» на основе собственной лавки. Проверить кнопку закрытия/страницы 800×360 и фактический экран телефона.
2. Арбитраж: зафиксировать время последнего API-снимка, нажать «Лучший план», проверить известные 100 покупка/92 скупка. Для *непроверенных* 100 с резервом 10% план ≤90; после ручной проверки спроса 92 план ≤92. Повторить при приходе новой цены/количества, старый маршрут обязан блокироваться.
3. Проверить, что «Продают» означает покупку у лавки, «Скупают» означает продажу ей. Для одной лавки с продажей 120k/скупкой 160k должна появляться **условная** связка при положительном спреде за вычетом комиссии; не совершать реальную сделку.
4. В калькуляторе ввести 1000000, 10000000, отрицательное число и дробь: проверить разделители и вычисление 1м ×10.
5. Осмотреть страницы пресета, ценовые подсказки «Рынок / Скупка / Сегодня» и статус очереди в режиме ТЕСТ (никаких реальных покупок, продаж, выставления). Для починки нативного «Выставить» нужны логи MonetLoader и пример серверных диалогов без секретов.
6. Регрессии: иконки, пресеты, журнал, 3D-маркер, переключение сервера, состояние открытой/закрытой лавки, reload. Не запускать массовые реальные операции ради теста.

## Нерешённое

- Реальный сервер может изменить спрос между двумя лавками **в любую секунду**. При покупке 100 и доступной скупке 92 остаток восемь; никакой один API-снимок не гарантирует их перепродажу. Даже 10% буфер не отменяет проверку непосредственно перед закупкой.
- Нативное выставление продажи/скупки, UI размер/свайп/модальные окна, GPU/ARM64 reload после этого релиза и игровой пакетный порядок не проверены на телефоне; отдельный старый Java crash без traceback остаётся без диагностики.
- Рыночные медианы — медианы предложений, не средние цены прошедших за сегодня сделок. Не выдавать их за совершённые продажи.
