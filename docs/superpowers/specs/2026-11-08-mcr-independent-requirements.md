# Уточнённое требование: самостоятельный полный MCR

Последнее прямое требование пользователя заменяет ограничение предыдущего preview:
нужны все исходные экраны, управления, настройки и механизмы MCR, доступные без
ключа MCR бессрочно. Не заменять их прежним UI или другой программой под его шапкой.

Сохранение исходной авторизации было свойством первого preview и больше не является
целью конечного продукта. Сейчас установленный preview всё ещё её сохраняет;
исправление геометрии арбитража не является выполнением автономности.

Должны остаться исходные окна и их модель поведения: продажа/скупка, инвентарь,
пресеты, темы и размеры, биндер, объявления/задержки, налоги, аренда, охрана,
шкаф, калькулятор, заметки, журнал. Для локальных механизмов должны отсутствовать
запросы лицензии и зависимости от полей ранее сохранённого ключа.

Исследование выявило зависимые участки: auth lifecycle, центральные списки,
сохранение пресетов и основных настроек, подготовка продажи, разбор инвентарных
диалогов, журнал. Проверять исходные обработчики по одному, не подменять состояние
успешным ответом выдуманного сервера и не удалять игровые проверки количества/ACK.

Проверка приёмки: чистая отдельная конфигурация, ключ отсутствует, MLoader отключён,
сервисы MCR недоступны. Все локальные управления должны открываться, настройки
сохраняться после перезапуска; торговые сценарии проверяются отдельно на фактических
ответах игры. Нельзя использовать текущий сохранённый ключ как доказательство.

Общая серверная база, чужая облачная история и иные удалённые данные требуют
доступного источника либо самостоятельной локальной реализации. Точный перечень
эквивалентных возможностей отмечается по результату проверки; не обещать доступ к
данным чужого сервера только на основании наличия клиентского кода.

Статус: требования зафиксированы, auth-independent сборка пока не реализована.
