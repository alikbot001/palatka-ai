# Palatka AI v2.2.6 — исправление сетевого слоя (27.10.2026)

## Причина обращения
На Android после v2.2.5 перестали обновляться данные рынка через API. **Точный HTTP-код и тело ошибки с телефона не предоставлены**, поэтому единственную причину сбоя доказать нельзя. Анализ показал несколько дефектов/неустойчивых мест на стороне скрипта и отдельную зависимость от API стороннего сервиса.

## Что исправлено в коде

1. `src/10_market.lua`: фоновый HTTPS GET теперь передаёт из `effil` только простые значения `status, body, err`; обработчик совместим и со старой тестовой формой ответа-таблицы. Исправлены разделение ошибок транспорта и HTTP, состояния потока, таймаут 45 с и защита callback. Сохраняется только однодоменный HTTPS-redirect — **без downgrade на HTTP**.
2. Нормальное отображение кодов **401/403 (доступ/авторизация), 404 (endpoint), 429 (rate limit), 5xx, ошибки сети/TLS, пустой ответ, HTML вместо JSON, некорректный JSON и API `ok=false`**.
3. Данные последней успешно полученной выгрузки остаются доступными при сетевом сбое **с пометкой устаревшего кэша**. На новый сервер кэш старого сервера не переносится.
4. Предусмотрен backoff при повторных ошибках (до 15 минут; 429 не раньше чем через 5 минут), но нажатие «Обновить» разрешает ручную попытку. Нет дополнительных HTTP-запросов в каждом кадре.
5. Устаревший ответ запроса к другому серверу не может заменить рынок текущего сервера. При ошибке обработки API снимок откатывается на последний рабочий. Кэш пишется лишь после валидации JSON и пересборки.
6. Ник игрока определяется несколькими SAMP-функциями, включая локальный ID, когда доступны; незнакомый ник не подменяется чужим `DsPic`. Параметры URL экранируются. Если ника нет, он не выдумывается.
7. В UI лавок показываются код/причина ошибки, факт использования кэша и пауза перед автоматической попыткой. Версия в UI, метаданных и исходниках — **2.2.6**.

## Важное ограничение — внешнее API

Palatka AI обращается к `https://va-ta.com/api/shops/pull`, сервису другой программы **Market Helper**. Независимость Palatka AI сохранена: никакого импорта модулей, токенов, конфигураций и платных функций Market Helper нет. Доступность и публичность именно этого endpoint для сторонних клиентов **не подтверждены**. Если сервис требует разрешения, ограничивает доступ или больше не отдаёт формат `shops`, код не может это законно или технически гарантированно исправить. Не подменяли API случайным сервисом: опубликованный API Arizona Market имеет иную схему и нет подтверждения поддержки Mobile I–III (101–103) в нужном формате.

Невозможно обеспечить 100% успешность запросов к независимому серверу. Исправлены действия клиента при отказах и добавлена диагностика, чтобы отличить серверную проблему от ошибки скрипта.

- `python3 tools/verify_embedded_icon_bank.py`: **8028/8028**, хэши PNG и byte offsets — **OK**.
- `texlua tests/test_*.lua`: **60/69 PASS** (покомпонентные результаты — `docs/v226_texlua_results.json`). Девять тестов не смогли запуститься под texlua: восемь требуют LuaJIT `bit`/FFI, один использует оператор `+=` не из синтаксиса Lua 5.3.
- `texlua tests/test_v226_network.lua`: **PASS**, сценарии 200, 403, 429, устаревший ответ, чужой сервер, API-отказ, повреждённый JSON, SSL/TLS, URL-encoding, сохранённый кэш.

**На телефоне, в MonetLoader и по живому сервису API эта версия не тестировалась.** Эмуляция HTTP не доказывает доступности DNS, TLS, токена или сети в Android. Ранее успешные телефонные проверки иконок относятся к прежним версиям.

## Короткий сценарий проверки Android

1. Установить `palatka_ai.lua` версии 2.2.6, сохранить прошлую Lua отдельно как резервную копию. Настройки/пресеты не удалять.
2. Зайти в игру на Mobile I/II/III → `/crr` → «Лавки» → «API» → «Обновить». Проверить, что через разумное время выводится количество лавок либо **точная категория ошибки**.
3. При ошибке проверить подключение через браузер и повторить один раз на Wi-Fi/мобильном интернете. При 401/403 не зацикливать запросы: вероятно требуется разрешение владельца API; при 429 следовать паузе.
4. Если есть сохранённые цены, убедиться, что при сбое они остаются видны с пометкой устаревших. При смене сервера не должны отображаться предложения предыдущего.
5. Прислать текст ошибки из UI и несколько строк `standalone.log`, **предварительно удалив личные данные и любые секреты**. По ним уже можно установить реальную причину на устройстве. Торговые покупки/продажи не нужны.
