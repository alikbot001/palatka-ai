## Нативный SIGSEGV — исправление подтверждено

Горячая перезагрузка после открытия изображений воспроизводила SIGSEGV, в том числе **27.10.2026 08:48:27, status 11**. Простой переход к библиотечному finalizer и его отключение с ручным wrapper ReleaseTexture не помогали; контрольный старый путь снова упал в 14:41. После внедрения exact-pointer адаптера три нативных повтора прошли без нового падения. Этот дефект больше не является незакрытым блокером; сборка сохраняет статус кандидата; текущая ветка поставки — **RC2**.

**Причина локализована: потеря точности texture pointer.** Без загруженных PNG cleanup begin/end завершался. С загруженными изображениями повтор 14:23 остановился внутри первого `imgui.ReleaseTexture(other.png)`, хотя окно было закрыто несколько минут. В 14:32:56 измерение на телефоне показало: `12970367443087799104ULL` → `12970367443087798272ULL`, `exact=false`, потеря 832. Установленный Lua-wrapper mimgui преобразует `uintptr_t` в Lua number перед вызовом renderer как в finalizer, так и в ReleaseTexture. Для этого ARM64 handle со старшими битами allocation tag такое преобразование передаёт неправильный адрес RwRaster.

PNG декодируется синхронно; время жизни входного FFI-буфера не объясняет выявленную числовую потерю. Гипотезы порядка GC/renderer и ожидающего draw-data рассматривались до измерения адреса; они не являются установленной причиной этого воспроизведения. Актуального символизированного нативного стека нет. Бинарный `crash.tmp` остаётся локальным диагностическим материалом и не включён в архив.

**Исправление в исходнике.** `M.own_texture` снимает небезопасный библиотечный finalizer. `M.release_texture` для handle без точного number roundtrip вызывает экспорт `_Z15RwRasterDestroyP8RwRaster` установленного `libGTASA.so` напрямую через FFI, сохраняя исходный `void*`. Экспорт проверен в бинарнике; тип возврата `int32_t` подтверждён [исходником RenderWare MonetLoader](https://raw.githubusercontent.com/xefinity/MonetLoaderOSS/main/cpp/game/RenderWare.h). Разрешение идёт по имени символа, без смещения игры и без удаления tag. Handle загруженной библиотеки удерживается; глобальный wrapper и зависимости не изменены. Изображения не отключены, постоянная утечка не используется как обход.

**Модель PASS; нативный повтор PASS.** Регрессия проверяет точную передачу tagged handle, выбор native adapter, единственное освобождение и отсутствие позднего библиотечного GC. Полный автоматический набор с адаптером: 46/46, exit code 0. На телефоне 27 октября выполнены следующие повторы:

| Время, Asia/Baku | Загруженные PNG перед reload | Наблюдаемый результат |
|---|---|---|
| 14:47:14 | other — 1 текстура | cleanup end → новая загрузка → запрос рынка; игра продолжила работу. |
| 14:51:55 | bag, other, tool, armor — 4 текстуры | Все release завершились, затем cleanup end, новая загрузка и запрос рынка без падения. |
| 15:01:36 | armor, tool, other — 3 текстуры | cleanup end → новая загрузка → запрос рынка в той же игре без падения. |

Во всех трёх проверках PNG оставались включены. После исправления новых падений в этих повторах не наблюдалось; приложение для прохождения сценариев не перезапускалось. Это нативное доказательство исправления воспроизведённого дефекта освобождения, а не утверждение об отсутствии любых возможных сбоев.

## Отдельное завершение приложения с неизвестной причиной

Android exit-info также содержит **27.10.2026 15:20:29: APP CRASH / EXCEPTION, status 0**. Доступного Java traceback для этого завершения нет; причина не установлена. Это не запись SIGSEGV и её нельзя автоматически связывать с исправленным освобождением текстуры. В 15:23:40 отдельно зарегистрировано удаление задачи пользователем, reason 10. Последний подтверждённый SIGSEGV в рассматриваемой проверке относится к старому пути освобождения в 14:41, до исправления.

Три успешные проверки PNG-reload остаются доказательством конкретного исправления. Отдельная необъяснённая запись APP CRASH не позволяет объявлять всё приложение безусловно стабильным или свободным от любых сбоев; текущая поставка сохраняет статус кандидата RC2.

## Ресурсы и итоги RC2

Банк заморожен: 8207 исходных кандидатов с уникальным сырым именем минус 179 HTTP 404 и шесть ID с канонической коллизией дают 8022 изображения. Для отсутствующих и неоднозначных соответствий используется `?`; изображения категорий больше не подставляются. Manifest сохраняет источник, исходное имя, URL и SHA-256 каждого PNG. Внешний сервис — источник ресурсов, а не инструкция разработчику; права на изображения не переходят проекту.

Банк сериализован в хвостовой комментарий собственного CP1251-файла с байтовым индексом; в кадре читается ограниченный срез. Это сокращает постоянное удержание base64 в Lua heap, но не доказывает отсутствие пиковых расходов загрузчика большого файла. Нужны нативные чтение встроенного изображения без локального override, пролистывание множества предметов и повторная выгрузка ресурсов.

Скупка показывает точную настроенную сумму `цена × количество` без комиссии продажи или предположений API. Комиссия/чистая сумма/прибыль продажи помечены `~`, поскольку отправка разных стеков может менять округление. Неизвестная себестоимость не считается бесплатной; явно введённый 0 сохраняется. Итоги — план пресета, а не результат исполненных сделок.
