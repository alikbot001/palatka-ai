# Palatka AI RC4 — количество и мобильные карточки (27.10.2026)

**Статус:** кандидат для нативной проверки. Этот Lua ещё не устанавливался на MonetLoader; реальные игровые сделки не выполнялись. Прошлые телефонные скриншоты относятся к предыдущим сборкам и НЕ проверяют RC4.

## Проверенная по исходникам причина риска «1 шт. вместо 45 000»

В предоставленном ранее `Market_Helper_FULL(1).zip`, модуль `Market_Helper.lua`, ветка `_mh_capture_own_shop_from_pending()` собирает слот без явного количества как `rec = {... qty=1 ...}`. Позже `_crf5h()` передаёт `qty` в `/shops/push`. Palatka AI загружает `/shops/pull` и трактовала `slot.qty=1` как одну штуку. **Это доказанный путь возникновения неверного API-количества**, но причинную связь с конкретной лавкой дров подтвердить без её игрового пакета нельзя. Один мобильный RPC-слот не обязан содержать реальное количество ресурсов. ПК-клиент/источник может передавать иные поля или собирать остаток иначе; конкретное различие протоколов текущего сервера не подтверждено.

## Сделанные изменения

- `src/10_market.lua`: `live_offer_quantity` сверяет наблюдение только по серверу, номеру и владельцу лавки, точному item/enchant, стороне и цене. Используется только явно известное количество, наблюдённое не старше 120 секунд, пока меню лавки открыто. Никакой подстановки произвольной лавки/номера/цены. API-количество сохраняется до **явного** подтверждения пользователем; исходное API-значение остаётся `snapshot_qty`. Не делаем HTTP/запись/скан всего рынка в каждом кадре.
- `src/45_live.lua`: извлекаются `qty`, `count`, `quantity` либо явно помеченные `шт.` (например `45000`, `45 000`, `45.000`). `amount` остаётся ценой и НЕ используется как число предметов. Если количество не показано, оно `nil`, а не `1`.
- `src/62_ui21_shops.lua`: понятные карточки с крупной кнопкой «Предложения», крупные «Подробнее» и «Метка»; API-объём помечен как непроверенный. В модальном окне одновременно показаны API и игровое наблюдение, предупреждение о расхождении, действия «Принять количество из игры» и «Подтвердить вручную». Нельзя редактировать устаревшее предложение. Детали имеют собственную прокрутку, фиксированные стрелки и нижние кнопки.
- `src/63_ui21_arbitrage.lua`: отдельная большая кнопка «Предложения» для каждого предмета, а для каждой конкретной лавки — «Выбрать / Снять выбор», «Уточнить», «Метка»; направление и цена не скрыты в названии. Количество по API отделено от количества, проверенного человеком/полученного из игры.
- `src/12_arbitrage_groups.lua`: подтверждение сохраняет `qty_source=game/manual` и исходный API-объём. При изменении числового поля от подготовленного игрового значения источник становится ручным. Новая загрузка API отменяет локальную коррекцию, не превращая её в вечный остаток.
- Никаких игровых покупок/продаж, загрузки PNG или новых зависимостей не добавлено. Старые пресеты, журнал, арбитраж, калькулятор, иконки и экспорт сохранены.

## Границы достоверности

API `/shops/pull` — серверный снимок объявлений, а не обещанный игровой остаток. Скан открытого меню/игрового RPC может НЕ включать количество; тогда оно должно оставаться неизвестным, сколько бы хотелось видеть «45 000». Ручная проверка — отдельный источник, но не гарантирует последующее наличие. ЦР даёт ценовые ориентиры, а не подтверждённое количество. Конфликтующие цифры не суммируются автоматически. Коррекция предложения применяется только к текущему снимку и сбрасывается новой загрузкой рынка. Автоматический арбитраж, пока не получено подтверждение, использует исходный API-объём с ранее введёнными ограничениями. Если API показывает `1`, скрипт не заявляет `45 000` без дополнительных данных.

## Короткая нативная проверка без сделок

1. В API найти дрова и лавку, где показано `1`, открыть «Подробнее», проверить предупреждение и время обновления. Скриншот номера, цены и объёма; не покупать.
2. Открыть **именно эту лавку** в игре, переключиться на «Скан лавки» и посмотреть количество. Вернуться к API-предложению: проверить одновременно обе цифры, если RPC содержит остаток. Если видна «Количество неизвестно», записать это — не подтверждать 45 000 наугад.
3. Если игровое количество явно равно 45 000, нажать «Принять количество из игры» и убедиться, что арбитраж показывает подтверждённый объём. Или указать 45 000 вручную только после самостоятельной проверки. После API-обновления должна восстановиться исходная API-цифра/неподтверждённость.
4. Пройти «Арбитраж → Предложения → Выбрать / Снять выбор → Уточнить», затем проверить кнопки «Лавки → Предложения → Подробнее», стрелки ▲/▼ и свайп на телефоне.
5. Если скан не получает объём: прислать обезличенный лог или сырой серверный пакет только этой лавки с ценой и именем предмета, без аккаунтов/токенов. **Не проводить реальные сделки для теста.**
